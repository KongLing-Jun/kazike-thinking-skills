# 三个分析技能的实际请求验证

日期：2026-08-28。测试方式：读取各技能的 `SKILL.md`，按指定用户请求生成实际答复，之后检查约束与技能流程。未联网，未调用外部服务，未联系他人，未安装软件，未修改技能。下文是测试生成的答复，不表示已完成外部核查、用户访谈或咖啡店实验。

## 1. claim-fact-checking

### 测试请求

> 请核查：朋友说某培训班学员收入平均涨50%，所以每个人都值得报名。我没有课程名字、数据或链接，这次不能联网。

### 实际答复

目前能检查的是这句话的推理；**“平均涨50%”没有可核查的材料，暂时不能确认，也不能判定为假。** 本次不会联网。

| 主张 | 类型 | 核查状态 | 依据与出处 | 适用限制 |
| --- | --- | --- | --- | --- |
| 某培训班学员收入平均上涨50% | 可验证事实 | 证据不够 | 仅有朋友转述，没有课程名称、原始数据或统计说明 | 不知道统计哪些学员、哪个时期、收入如何定义，也不知道50%如何计算 |
| 收入增长由该培训班造成 | 隐含的因果推论 | 现有材料不支持 | 即使增长数字准确，也没有对照或其他因果证据 | 涨薪可能还受工作变动、行业环境、学员原本的能力等影响；这些只是待排查的解释，不是已发生的事实 |
| 每个人都值得报名 | 价值判断与普遍化推论 | 无法由上述均值推出 | 没有每个人的收益分布、课程成本、适合程度和个人目标信息 | “值得”取决于个人情况；平均数也不代表每个人都增长50% |

最关键的推理问题有三个：

1. **平均值不等于个人结果。** 即使平均值属实，也不能推出人人受益。还需区分“各人收入涨幅的平均”与“全体平均收入的涨幅”。
2. **上课后收入增加，不等于上课导致收入增加。** 需要了解没有上课时可能发生什么，以及是否只统计了成功、毕业或愿意回复的学员。
3. **收入增长不等于报名划算。** 学费、投入时间、收入波动和个人目标都没有进入判断。

更稳健的改写是：

> 朋友转述称某培训班学员收入平均上涨50%，但尚无材料核实统计口径或原因。这个说法不足以判断任何具体个人是否值得报名，更不能推出人人都该报名。

目前可以相信的范围，仅限于你收到了这条转述；统计真实性和培训效果都仍未知。**尚未完成的外部核查**包括课程身份、原始统计、样本与失访情况、收入定义、观察期及对照情况。

下一步最值得补充的是朋友所依据的原始材料，尤其是带有样本、时间和统计口径的报告，而不只是宣传截图。这次缺少这些材料，因此不作报名建议。

### 执行检查与发现

- 通过：遵守禁止联网；没有写“已核实”；没有把证据缺失误判为虚假。
- 通过：拆开统计事实、因果推论与个人价值判断；保留“平均”和“每个人”的量词差异。
- 通过：建议改写只保留“朋友转述”这一已提供信息，没有添加效果证据。
- 无阻断问题。技能第2步使用“检索原始出处”，而边界只显式写“没有联网工具时”；在“工具可用但用户禁止联网”的场景，可增加明确措辞覆盖用户禁网要求，减少机械执行搜索的风险。此次实际答复已按用户约束处理。

## 2. two-sided-steelmanning

### 测试请求

> 我们可以本月上线新系统，也可以推迟一个月。现在已知测试大部分通过，但有一个偶发的数据同步故障还没查明。团队认为延迟会错过一次演示机会。请双向钢人论证。

### 实际答复

真正的选择是：为了保住本月的演示窗口，是否接受一个尚未查明的数据同步风险；或者用一个月换取排查与验证时间，同时承担错过演示的代价。下面先比较这两条路径。用隔离环境演示、分阶段开放等中间方案暂不纳入二选一，但它们可能改变这项取舍。

| 比较项 | 本月上线的最强论证 | 推迟一个月的最强论证 |
| --- | --- | --- |
| 已有依据 | 大部分测试已通过，说明已有一批功能获得测试支持；团队认为本月存在演示机会 | 有一个未查明的同步故障，意味着仍有关键不确定性；“大部分通过”不能说明剩余风险很小 |
| 最强理由 | 如果故障影响能够被限制、及时发现和恢复，本月交付可以保住演示，并更早获得实际使用反馈；不应仅因存在任何未解决问题就无限延迟 | 同步故障可能损害数据可信度；在原因、影响和恢复方式未知时，上线可能把排查问题变成生产事故。低出现频率也不能证明低损失 |
| 成立条件 | 故障不会造成无法接受的数据后果；有经过验证的隔离、监测和恢复手段；演示确实需要本月上线 | 这一个月有明确的复现、定位、修复和验证计划；延期能实质降低风险；错过演示的代价可承担 |
| 最好收益 | 保住演示，验证交付能力，并较早获得反馈 | 以更充分的证据决定是否上线，减少带故障进入真实环境的可能 |
| 最大风险 | 故障在生产中扩大影响，损害用户信任；当前不知道损害是否可恢复 | 演示机会无法挽回；一个月后问题仍未解决，只增加了时间成本 |
| 最难回应的反对理由 | 既然故障没查明，凭什么确信损害可控、数据可以恢复？“偶发”本身不能作担保 | 为什么恰好一个月能降低风险？如果没有排查计划，延期本身不会修好系统 |

双方真正的分歧，不是“重视速度”还是“重视质量”，而是**当前风险能否被约束，以及额外一个月能否换来足够的风险下降**。演示的实际价值、是否必须连接真实数据，以及故障造成的损失范围，目前都缺少证据。

最能改变判断的一个问题是：**目前有没有经过验证的证据，证明这个同步故障即使在上线后发生，也不会造成不可恢复的数据丢失或错误扩散？**

### 执行检查与发现

- 通过：双方均陈述已有依据、成立条件、收益、风险与最难回应的反对理由。
- 通过：没有把“偶发”说成“低风险”，没有把“多数测试通过”说成“已安全”，没有假设推迟必能修复。
- 通过：首轮仅提出一个需要用户回答的问题；没有提前宣布最终推荐。表内反对理由是论证内容，不是额外要求用户逐项回答的追问。
- 通过：将演示机会保留为“团队认为”，未虚构商业合同、客户承诺或收入损失。
- 无阻断问题。一个可改善点是，技能可提示将“上线”和“演示”是否必须绑定作为常见的选项边界检查；此次答复已说明中间方案未纳入对照，避免把题目变成伪二选一。
- 本测试只覆盖第一轮；没有收到用户的关键问题回答，因此第二轮推荐、反转条件和行动尚未被实际验证，不应宣称完整两轮流程均通过。

## 3. minimum-experiment-design

### 测试请求

> 我想辞职去开咖啡店，帮我设计7天的最小实验。我暂时最多有500元，不想联系陌生人，也不想影响当前工作。

### 实际答复

这7天先不验证“能否马上辞职开店”，而是验证一个能否决继续投入的前提：**你是否愿意反复做咖啡店里不那么浪漫的基础工作，并能在不影响现有工作的情况下完成。** 在不接触潜在顾客的限制下，这个实验无法证明市场需求或盈利能力；通过也只支持下一步调研。

三个关键假设，按对辞职决定的影响排列：

1. **有人愿意按足以覆盖成本的价格持续购买。** 这是经营成立的核心，但目前没有证据；这次不接触陌生人，也不把熟人夸奖当成需求证明，所以暂不验证。
2. **你能承受开店到稳定经营之间的资金和生活压力。** 需要个人现金流、开店成本等资料；500元是本次实验预算，不能据此推断你的全部储蓄。七天不产生可靠经营收入数据。
3. **你愿意承担重复制作、清洁、库存和记账等日常工作。** 这次优先验证它，因为能在现有限制内取得直接行为证据；如果明确不愿持续做，这会改变下一步决定。它不是前两个假设的替代品。

### 七天安排

全部安排在现有工作的非工作时间；每天最多30分钟，不占用睡眠、加班任务或家庭必要事项。30分钟只是本次低干扰试验的资源上限，不代表真实开店工作量。先用已有器具和材料，**默认支出0元，硬上限500元；不租场地、不买大设备、不辞职、不借款、不对外营业。** 若现有条件不足，先记录缺口，不为完成实验强行采购。

| 天数 | 动作 | 记录什么 |
| --- | --- | --- |
| 第1天 | 在非工作时间做一次15分钟的小流程：准备已有器具、制作一份自己平时会喝的饮品、清洁复位；没有制作条件时只做器具整理与清洁，并明确这是低真实性的替代任务 | 实际耗时、最不愿做的环节、当晚休息是否受影响，作为后续比较基线 |
| 第2天 | 用相同流程重复一次，把准备、制作、清洁分别计时；只用已有材料 | 是否比第一天更愿意或更抗拒，耗时差异及原因 |
| 第3天 | 再重复一次，并登记所耗材料；依据已有收据或包装信息算这一份的可确认材料成本 | 可确认金额与未知金额分开；不把材料成本当成完整开店成本 |
| 第4天 | 在同样的时间上限内做一次“收店”：清洁、清点剩余材料、记录损耗和需要补充的物品 | 是否主动省略了不喜欢的环节，是否愿意再做，具体原因 |
| 第5天 | 完整重复“准备—制作—清洁—记账”，不追求拉花或新品 | 是否能完成闭环；没完成是时间不足、条件不足还是不愿做 |
| 第6天 | 再做一次相同闭环；只在正常可用的休息时间进行，不刻意熬夜或增加疲劳 | 重复后的态度与最初新鲜感有何不同，是否影响次日工作准备 |
| 第7天 | 不加做任务，回看记录，填写“愿意继续的环节、持续抗拒的环节、仍不知道的事”，形成下一步结论 | 支持继续、需要调整或应暂停的具体证据 |

制作饮品不要求额外喝下，也不增加平时的咖啡因摄入；避免为了测试而浪费材料。若没有基本制作条件，本周只能检验清洁、库存和记账意愿，不能声称检验了咖啡制作或门店运营。

### 指标和预先约定的判断条件

每天只记一行：`日期｜任务｜分钟数｜实际支出｜完成/未完成及原因｜最抗拒的环节｜是否占用睡眠或工作｜是否愿意下周再做及原因`。次日再补记是否影响精力或工作安排，不把所有疲劳都自动归因于实验。

- **立即停止或缩减：** 一旦实验开始侵占睡眠、必要工作时间或让你感到身体不适，当天停止；后续改为短记录，不靠硬撑完成。任何采购可能突破500元，停止采购。这些边界直接来自“不影响工作”和预算限制，不是成功率估计。
- **支持下一步调研：** 能在真实可用的时间里反复完成基础流程，记录中没有发现工作与休息被挤占，而且你在看清清洁、记账等环节后仍愿意继续。这里不设“完成80%就算成功”之类无基线门槛；它只是探索性证据，不能导出辞职结论。
- **调整后再测：** 未完成主要因为器具或时间安排不合适，或者这周恰逢特殊工作压力，就把结论标为“不足以判断”，只调整一个条件再试，不事后降低要求宣布成功。
- **暂停开店投入：** 基础任务持续让你抗拒，你不愿在类似条件下继续，而且记录显示这并非一次突发事件造成。先重新考虑自己想要的是喝咖啡、做咖啡，还是经营一家店。

这次能新增的知识，是你对一小部分重复经营任务的真实反应，以及当前生活能否容纳这样的探索。它不能回答客源、定价、选址、完整成本、经营许可、全日劳动强度或能否盈利；不得用它作为辞职依据。

**明天的第一个动作：** 找一个不会挤占睡眠或工作的15分钟空档，用现有条件做第一天的小流程并记一行。如果连这样的空档都没有，就记录“本周条件不允许”，不牺牲当前工作来证明决心。

### 执行检查与发现

- 通过：没有安排辞职、借贷、租赁、设备大额采购、联系陌生人或占用上班时间；没有执行任何支出或联络。
- 通过：七天、默认0元、最高500元、每天上限、停止条件、记录方法和明天动作明确；资源上限说明了依据。
- 通过：需求和资金是更关键但当前无法有效验证的假设，未以家庭练习冒充市场验证；没有将熟人称赞当成付费需求。
- 通过：没有捏造结果、投资回报或“成功率80%”；通过只支持下一步调研，不支持辞职。
- 无阻断问题，但存在两个设计局限：其一，受约束时最重要的假设无法直接验证，技能可更明确要求解释“为何退而验证必要前提”；其二，“愿意持续做”“不影响工作”缺乏稳定基线，短期自评易受新鲜感影响。此次用逐日行为记录、首日基线、探索性结论和明确不可推断范围控制误用，没有把这些指标升级为商业可行性判定。
- 本测试验证的是实验设计答复；未开展七天实验，无法验证真实执行效果或用户接受度。

## 汇总

三项均能生成符合给定边界的实际答复，未发现阻断问题。值得补充的技能措辞是：明确用户禁止联网时不得检索；钢人分析检查选项是否必须绑定；最小实验说明核心假设不可测时的选择降级与结论限制。第二项只验证首轮，第三项只验证设计输出，不能据此声称后续决策或现实结果已通过验证。

### 2. minimum-experiment-design 实际答复

可以设计，但这7天的结论只能是**“是否继续探索开店”**，不能是“已经证明可以辞职”。不联系陌生人、不影响工作、最多500元，会限制我们能拿到的证据。

三个关键假设，按对决定的重要性排序：

1. **有足够的人愿意持续付费购买。** 如果不成立，店就难以经营；目前没有需求证据。你的限制下，这周无法有效验证真实付费需求。
2. **你能承受经营成本和收入不确定性。** 目前缺少成本与个人财务资料。500元只是实验上限，不能推断为你的总储蓄；七天也不能产生稳定盈利证据。
3. **你愿意反复承担至少一部分日常运营任务。** 暂以你会亲自参与运营为前提；如果明确不愿意，这会改变开店方式或让你停止投入。

这次改测第三个必要前提，因为它在限制内能取得直接行为证据。**它不能替代市场需求和财务可行性验证。** 如果你打算完全雇人运营，这个实验与实际选择的关系就弱，应先调整假设，而不是照做凑满七天。

#### 实验边界

- 周期7天；只用已有的非工作空档，每天最多20分钟。这个上限是低干扰设计，不是真实开店工时；一旦挤占睡眠、必要事务或工作准备，就停下。
- 默认支出0元，最多500元；先用已有器具、饮品材料和纸笔。不为完成实验购买设备，不租场地、不借贷、不辞职、不对外营业，也不安排任何外部联系。
- 制作的是你原本就会准备的一份饮品，不要求多喝咖啡或额外消耗材料。没有制作条件时可只做清洁、清点和记账，但要把结论限制为对这些任务的反应。

| 天数 | 具体动作 | 要留下的证据 |

| 第1天 | 用已有条件做一次“准备—制作一份饮品—清洁复位”，最多20分钟 | 分环节耗时、未完成部分、最不愿做的环节；这是后续比较的基线 |

| 第5天 | 重复“准备—制作—清洁—记账”，仍守住20分钟上限 | 哪一步完成不了，原因是时间、条件还是意愿 |

| 第7天 | 只复盘，不加任务：回看记录，回答是否愿意下周再做同类流程及原因 | 形成继续、调整或暂停的结论，写明未知项 |

每天记录一行：`任务｜分钟数｜支出｜完成情况和原因｜抗拒/愿意的具体环节｜是否挤占工作或休息｜下次是否愿意再做`。次日补记精力或工作安排是否受影响；只记录观察，不自动把一切疲劳都归因于实验。

#### 事先约定的判断条件

没有你的历史基线，不预设“完成80%就能开店”之类门槛。第1天先建立耗时和任务反应基线，其余判断只用于下一步探索：

- **停止边界：** 出现工作或必要休息被挤占、身体不适，立即停止当日任务；预算可能超过500元时停止采购。不能靠压缩睡眠换一个“通过”。

- **调整后再测：** 主要障碍是现有器具不足、试验周异常繁忙，或替代任务与真实运营差别过大，结论写“不足以判断”，只调整一个条件再测。
- **暂停投入：** 回看多日记录后，你明确不愿继续这些基础任务，并能指出重复出现的原因。先重新考虑是喜欢咖啡本身，还是愿意经营咖啡店；这不是对你能力的最终判定。
