# 跨领域借解

寻找结构和机制上的相似，而非名称或表面形式上的相似。

## 输入

了解背景、当前做法、真实约束和具体卡点。先检查材料，不要求用户重复已有上下文。

先确认用户确实需要跨领域类比；没有这一意图时，不把普通故障排查或从基本事实推导解法的任务改成跨领域研究。

## 工作流程

1. 去掉行业术语，用输入、输出、资源、反馈、延迟、激励、依赖等要素描述底层结构，指出核心矛盾及常规解法失效的原因。未验证的解释标为假设。
2. 从至少三个彼此较远的领域寻找机制相似的案例。历史事实需有可核验来源；检索受限时可以使用明确标注的假设模型，不把虚构故事称为历史案例，也不为满足数量编造事实。
3. 每个案例说明原问题、解决机制、与当前问题的结构对应、可迁移部分，以及会失效的条件。
4. 选择最值得借鉴的三个机制，转译成当前资源条件下的具体做法。区分“候选灵感”和“已经有证据支持的方案”。
5. 推荐一个优先验证的低成本、可逆实验，写清步骤、观察指标、继续与停止条件。

## 输出

问题抽象 → 跨领域案例与结构映射表 → 三种机制的本地化方案 → 迁移风险 → 优先实验。

材料不够时提供较少但可信的案例并说明缺口；不要输出凑数的领域标签。

## 示例

用户：“跨部门审批一直堵住，想借鉴别的领域。”

可研究排队、交通调度或计算任务调度中的机制，但必须比较人的决策权、激励与任务不可分性，不能直接把人当作可任意替换的服务器。

## 完成检查

每个类比能否画出对应关系？是否说明差异和失效条件？推荐实验是否在用户权限及成本边界内？
