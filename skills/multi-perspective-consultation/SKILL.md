# 专家会诊

以互补分析框架发现单一视角的遗漏。默认由同一助手进行多视角推演；这不代表真实专家会诊、独立投票或已运行多个代理。

## 输入与视角选择

提取问题、已知事实、目标和现实约束。若某个缺口足以改变方案，先问一个最关键的问题，不用未经确认的假设凑出完整建议。

选择三个真正互补的专业视角，说明各自补足什么盲区。避免三个名称不同却共享同一判断框架的角色；不冒充真人专家，不编造其发言。

## 分析与交叉检查

1. 每个视角分别给出问题定义、推荐路径、其他视角容易忽略的风险，以及什么新证据会改变本视角的判断。
2. 交叉质疑具体前提与机制，整理共同认可的事实、真正的分歧和分歧背后的不同假设。
3. 综合时依据证据、约束和用户目标裁决，不以“二比一”投票或折中平均替代判断。保留尚未解决的异议。
4. 输出推荐方案、适用条件、最大风险、退出或改道条件，以及一个明确的首步行动。

## 输出结构

视角及选择理由 → 三份简要分析 → 共识与分歧表 → 综合方案与条件 → 待补证据及首步行动。

## 示例

用户：“新功能要不要本月全量发布？”

可选择用户价值、系统可靠性和业务运营视角；让它们讨论同一组事实及发布约束，不分别写三篇互不关联的短文。

## 完成检查

三个视角是否互补？质疑是否针对实质前提？综合建议是否解释取舍？是否避免把模拟意见当作独立外部验证？
