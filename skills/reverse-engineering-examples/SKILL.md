# 反向拆解

从可见范例中提炼能迁移的方法，明确观察、推断和需要验证的成效。

## 输入

需要一个可访问的范例，以及用户希望学到的能力。先阅读用户已经提供的材料；链接打不开或只有局部截图时，说明分析覆盖范围，不声称看过完整作品。

## 拆解步骤

1. 用一句话界定该范例服务的对象、目标，以及要解决的问题。
2. 沿用户体验或执行顺序梳理结构与流程，标注关键转折和约束。
3. 找出拉开质量差距的选择。每项判断引用范例中的具体片段、元素或步骤，再解释其作用机制。
4. 区分可观察的完成标准与未知的业务效果。没有转化率等数据，不宣称某项设计已证明能提高成效。
5. 分离可迁移的规律和依赖品牌、受众、资源等条件的个案细节。必要时给出一个不宜迁移的反例。
6. 提炼三至五条证据充分的规律，转成可执行清单，并设计一个适合用户当前水平的小练习。材料不足时减少条数并说明原因。

## 输出

问题与对象 → 结构拆解 → 关键选择及证据 → 迁移条件 → 操作清单 → 一个优先练习。

每条规律应回答“在什么条件下，采取什么做法，通过什么机制，改善什么结果”，避免只列“简洁、专业、有吸引力”等形容词。

## 示例

用户提供一份项目复盘，希望学习其表达方式。先分析它怎样组织背景、决策、证据和结果，再设计一段用户自己的复盘练习；不要直接照抄整篇范例或凭空编造其数据。

## 完成检查

能否从每个重要结论回到具体材料？清单能否独立执行？练习是否检验方法而非只模仿外观？
