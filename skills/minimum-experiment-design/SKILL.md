# 用最小实验替代空想

用现实反馈减少决策不确定性，优先检验最可能改变选择的假设。

## 设计流程

1. 明确用户正在考虑的选择或想法，以及想通过实验决定什么。
2. 只列出当前决定所需、尚未确认的关键假设，数量由材料和决策需要决定，不为凑数重测已确认事实或引入无关问题。按“如果不成立，是否会改变决定”及“当前证据有多薄弱”排序，选择一个优先验证；只有一个未知时直接围绕它设计。假设应能被观察或反驳。若最关键假设在现有限制下无法测试，解释为何改测另一个必要前提，以及它不能替代验证什么；若没有有信息价值的实验，就明确说明。
3. 围绕该假设设计最小实验。用户未设周期时以七天为候选；若客观上无法在七天得到有效信号，说明原因并提出更合适的周期，不承诺假结果。
4. 写清具体动作、时间与资源上限、观察指标、记录方法、继续条件、停止条件，以及实验结束后能新增什么知识。
5. 提前设定判断阈值，并解释依据。没有基线时，先测基线或将阈值标为待确认，不随意编造“成功率达到80%”等数字。
6. 给出明天可以开始的第一个动作。将计划和已发生的实验结果明确分开。

## 输出模板

- 要做的决定及必要的待验证假设，区分已经确认的前提。
- 优先假设及选择理由。
- 实验步骤、周期、成本上限和可逆性。
- 指标与记录方式；支持继续、调整或停止的条件。
- 能回答及不能回答的问题。
- 明天的第一个动作。

## 边界

不把辞职、贷款、公开发布个人信息等不可轻易撤销的承诺包装为“小实验”。涉及真实用户、支出、外部联络或数据采集时，先提出设计；执行仍需用户相应授权。没有请求，不创建日历、提醒或自动化。

## 示例

用户：“我想转行做培训，但一直犹豫。”

可以先验证自己是否愿意持续备课并获得有效学习反馈，采用小范围自愿试讲；不能仅凭一次好评就断言市场需求已被证明。

## 完成检查

实验测的是核心假设还是忙碌程度？结果能否改变决定？是否可逆且有成本上限？有没有在看到结果后再改成功标准？
