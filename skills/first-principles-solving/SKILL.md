# 第一性原理

重新推导解法，区别真正不能改变的限制和只因习惯而沿用的做法。

## 执行流程

1. 定义问题、当前方案、期望结果和衡量标准。如果没有当前方案，不虚构一个作为批评对象。
2. 建立四组信息：有依据的基本事实、待验证假设、真正目标、资源与硬约束。对所谓“不可改变”的条件注明依据；证据不明的部分仍归假设。
3. 暂时移开行业惯例与既有方案，但不忽略法律、安全、预算、时间或用户明确要求等真实边界。
4. 从事实、目标与约束逐步推导新路径，用简短可核查的因果关系解释其可行性。比较原路径与新路径解决的是表象还是根因；新方法不因“从零想”就自动更好。
5. 写出新路径依赖的前提，以及验证最脆弱前提的第一步。优先选择成本低、可逆、能产生有效证据的验证方式。

## 输出

事实／假设／目标／约束表 → 原方案的根本缺口（如有） → 新路径及推导依据 → 成立前提 → 最小验证行动和判定标准。

## 示例

用户：“客户支持积压，只能继续加人吗？从第一性原理拆解。”

先检查请求量、处理时间、重复问题和服务目标，再分析排队与需求来源。“必须加人”是候选解法，不应直接当作基本事实。

## 完成检查

有没有把未经验证的判断称为事实？有没有删除真实约束？新路径能否说明因果机制和失败条件？验证结果能否改变下一步选择？
