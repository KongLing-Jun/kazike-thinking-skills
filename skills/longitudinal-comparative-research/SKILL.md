# 纵横分析法

用历史解释当前能力，用可比对象解释相对位置，再提出有证据边界的未来判断。

## 研究范围与证据

确认研究对象及用户关注的问题。未指定截止时间时以执行日为截止日，并在结果中写明具体日期。涉及当下事实时使用可用的检索工具；没有联网能力时仅分析已给资料，明确资料截止时间。

优先官方材料、原始数据、论文、财报和当事人访谈。关键事实附来源、日期与必要上下文；多个报道转述同一原始出处不算多份独立证据。找不到证据的部分标注待核实，冲突材料并列说明。

## 分析流程

1. **纵向**：追溯诞生需求、环境、关键推动者、重要转折、成功与失败。解释哪些早期选择塑造了当前能力、限制与路径依赖，而不只排列年份。
2. **横向**：选择真正可比的对象，解释选取理由。按一致的维度、时间窗口和数据口径比较优势、短板、差异及用户选择或放弃它们的原因。缺失值写未知，不编造统一评分。
3. **综合**：把历史形成的能力和约束带入比较，解释现在的位置为何形成。
4. **未来**：提出三个有区别的可能情景，各写触发前提、支撑证据、早期信号和反证条件。没有足够依据时不赋予精确概率。

## 输出顺序

核心发现 → 时间线 → 比较表 → 机制分析 → 三种未来情景 → 待确认问题与来源。

默认可组织为约一千至三千字的研究简报；若用户要求不同篇幅则遵从。事实、推断和个人评价应能一眼区分，篇幅不足不以删除关键出处为代价。

## 示例

用户：“纵横分析某开源数据库。”

同时研究其设计演变与同类产品的取舍；在版本、部署模式和负载条件未对齐时，不把单一性能数字当作优劣结论。

## 完成检查

是否解释历史与现状的关系？比较口径是否一致？每条未来判断是否有前提和可观察信号？未检索时是否避免“最新”“截至今日已核实”等表述？
